01 문제 / 목적

비교, 지도, 서신 초안을 비롯한 기능의 흐름성이 중요한 웹사이트였습니다. 따라서 사용자가 suburb를 선택한 후 해당 지역으로 지도의 포커스가 원활히 이동하는 것이 중요했습니다.

02 역할

Django 프론트엔드 개발에 참여하였습니다. 배포 전 Smoke Test 체크리스트를 작성해 실행했고, Think-aloud 사용성 테스트에도 참여하였습니다. Common Technical Issues 가이드와 Startup / Backup / Recovery 절차를 문서화하였습니다.

03 제품 / 기능 설계

suburb 선택 값이 비교 화면, 지도, Score 색상, 서신 초안에 같이 반영되도록 흐름을 정하였습니다. Score 색상은 API 응답과 UI가 같아야 한다는 조건을 기준으로 삼았습니다.

04 개발 및 실행

프론트엔드 구현에 참여하였으며, 백앤드와 프론트앤드를 연결하였습니다.

05 검증

로컬과 호스팅에서 같은 suburb 선택 시나리오를 실행하였습니다. Score 색상 밴드는 API 응답, 코드 처리, UI 표시가 같은지 대조하였으며, 375 / 768 / 1440px과 브라우저별 주요 기능도 확인하였습니다.

06 문제와 개선

호스팅한 사이트에서 suburb 변경 시 지도의 포커스가 변경되지 않는 이슈가 발생했습니다. 반면, 로컬에서는 이러한 오류가 확인되지 않았습니다.

Deep Dive - ourSuburb

배포 환경에서만 발생한 지도 포커스 오류

사용자가 선택한 suburb를 지도에서 확인할 수 없는 문제를, 로컬과 호스팅 차이로 좁힌 사례입니다.

LOCAL 정상

suburb를 선택하면 지도가 해당 위치로 이동하였습니다.

HOSTING 오류 발생

같은 동작에서 지도 포커스가 이동하지 않았습니다.

문제

suburb를 선택해도 지도 포커스가 해당 위치로 이동하지 않았습니다.

↓
사용자 영향

비교 화면에서 선택한 suburb의 위치를 확인하기 어려웠습니다.

↓
재현

같은 suburb 선택 시나리오를 로컬과 호스팅 환경에서 각각 실행하였습니다. 로컬에서는 정상으로 실행이 되는 반면 호스팅 환경에서는 이슈가 발생하는 것을 확인할 수 있었습니다.

↓
분석

Mapbox 스타일 로딩 시점과 지도 컨테이너 크기 처리를 확인하였습니다.

↓
원인

스타일이 로드되기 전에 flyTo가 실행되었고, resize 처리가 빠져 있었습니다.

↓
조치

isStyleLoaded를 확인한 뒤에 flyTo를 실행하고, resize 처리를 추가하였습니다.

if (!map.isStyleLoaded()) {
  map.once('idle', () => moveCamera(lng, lat));
  return;
}
map.resize();
map.flyTo({
  center: [lng, lat],
  essential: true
});
↓
재검증

호스팅에서 같은 suburb 선택 시나리오를 다시 실행하였으며, 선택한 위치로 지도 포커스가 이동하는 것을 확인하였습니다.

↓
이슈 공유

LeanKit에 재현 환경, 재현 방법, 실제 결과, 기대 결과, 원인과 수정 내용을 정리해 공유하였습니다.
